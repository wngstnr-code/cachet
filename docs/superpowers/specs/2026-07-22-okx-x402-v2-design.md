# OKX x402 v2 Integration Design (D5/M5)

**Date:** 2026-07-22  
**Status:** Approved in conversation  
**Target:** X Layer Testnet (`eip155:1952`)

## Objective

Replace Cachet's hand-written x402 v1 payment guard with the official OKX x402
v2 Fastify middleware. The public gateway must reject unpaid requests, use the
OKX Payment Broker to verify and settle testnet payments, and execute Cachet
business handlers only after a payment is accepted.

This work completes the code portion of M5 and the credential-acquisition portion
of D5. A5.4 remains open until a paid request succeeds against the deployed public
gateway. Marketplace acceptance remains open until the same flow succeeds through
the listed OKX.AI service.

## Decisions

- Cachet is an HTTP seller/resource server. It does not implement or operate a
  facilitator; OKX operates the Payment Broker/facilitator.
- Use the official Fastify integration rather than a custom adapter or a reverse
  proxy: `@okxweb3/x402-fastify`, `@okxweb3/x402-core`, and
  `@okxweb3/x402-evm`.
- Run payments on X Layer Testnet only (`eip155:1952`). Mainnet and general
  multi-chain support are separate future projects.
- Use the existing testnet gateway address as the x402 receiving address (`payTo`).
- Preserve the existing paid-route scope and prices:

  | Route | Service price |
  | --- | ---: |
  | `POST /v1/verify` | `$0.02` |
  | `POST /v1/commit` | `$0.01` |
  | `POST /v1/mint` | `$0.50` |
  | `POST /v1/watch` | `$0.10` |

- `GET /v1/cert/:id`, health endpoints, and `POST /v1/challenge` remain free of
  x402 charges. Challenge bonds and mint insurance premiums remain separate
  on-chain Cachet mechanisms.
- Express prices as user-facing USD strings. The OKX SDK and Broker-supported
  payment metadata select the official testnet settlement stablecoin. Cachet's
  project-specific `MockUSDT` must not be advertised as the x402 asset.
- Keep `X402_BYPASS=1` for local development/tests only. The OVH deployment must
  use `X402_BYPASS=0` and `DEMO_MODE=0`.
- Do not change CI/CD, enable CLIP, add containers, open ports, register the ASP,
  or deploy contracts as part of D5/M5.

## Architecture

The payment middleware runs inside the existing Fastify gateway container:

```text
OKX.AI or external buyer
          |
          | HTTPS request / payment retry
          v
Cloudflare -> Caddy -> Cachet Fastify gateway
                              |
                              +-- free route -> Cachet route handler
                              |
                              +-- paid route -> OKX x402 v2 middleware
                                                   |
                                                   v
                                           OKX Payment Broker
                                                   |
                                                   v
                                           X Layer Testnet
```

The engine, gateway storage, Caddy configuration, contract client, and Docker
network topology remain unchanged. Only the gateway image needs replacement.

## Components

### Route pricing

`apps/server/src/x402/prices.ts` remains the single source of truth for protected
routes, descriptions, and prices. Its values are adapted into the official SDK's
route configuration. Tests assert that free routes are absent from this map.

### OKX payment server

The current `HttpFacilitator`, hand-built x402 requirements, and v1 payload are
removed. A thin Cachet wrapper will:

1. create an authenticated `OKXFacilitatorClient` using runtime credentials;
2. register the EVM `exact` scheme for `eip155:1952`;
3. initialize the SDK resource server and synchronize Broker-supported payment
   metadata;
4. register `@okxweb3/x402-fastify` middleware with the four protected routes;
5. let the SDK own the v2 challenge, payment verification, settlement, replay
   protection, and payment response receipt.

The wrapper preserves dependency injection so tests can use a fake facilitator
without network access or real credentials.

### Configuration

Production requires:

| Variable | Purpose |
| --- | --- |
| `OKX_API_KEY` | Broker API identity |
| `OKX_SECRET_KEY` | Broker request signing secret |
| `OKX_PASSPHRASE` | API-key passphrase |
| `OKX_BASE_URL` | Defaults to `https://web3.okx.com` |
| `X402_NETWORK` | Must be `eip155:1952` for this deployment |
| `X402_PAY_TO` | Existing gateway testnet address |
| `X402_RESOURCE_BASE` | Public HTTPS origin, `https://api.cachetprotocol.xyz` |
| `X402_BYPASS` | Must be `0` on OVH |

When bypass is disabled, the three OKX credentials must be present together and
must never be exposed in responses, logs, screenshots, images, or repository
files. Missing or partial credentials cause startup to fail. The former
`X402_FACILITATOR_URL` and project-token `X402_ASSET` settings are retired.

`X402_RESOURCE_BASE` prevents an internal HTTP URL from appearing in the challenge
when Fastify runs behind Caddy and Cloudflare.

### MCP adapter

`apps/mcp-server` remains a thin adapter rather than the payment authority. It
will continue returning a 402 result and the `PAYMENT-REQUIRED` value to its
caller, but its documentation and tests will use x402 v2 terminology and the
standard payment header rather than the legacy `X-PAYMENT` wording.

The public REST resource endpoint is the A2MCP listing target. Deploying a separate
network-facing MCP process is outside this scope.

## Request Flow

1. A buyer calls a protected public endpoint without a payment credential.
2. The SDK returns HTTP 402 with a base64-encoded `PAYMENT-REQUIRED` challenge.
   The decoded challenge uses x402 version 2 and includes the public resource URL,
   route description, `exact` scheme, `eip155:1952`, official testnet settlement
   asset, amount, timeout, and gateway `payTo` address.
3. The buyer selects the offered requirement, signs a testnet payment, and retries
   the same request with the SDK-defined payment header.
4. The gateway SDK authenticates to the OKX Broker. The Broker verifies and settles
   the credential on X Layer Testnet.
5. Only a successful settlement allows the Cachet handler to run.
6. The handler response includes the SDK's payment receipt header.

For `/v1/mint`, the x402 `$0.50` service fee and the existing Cachet insurance
premium are independent. D5/M5 does not change the premium calculation, gateway
allowance, contract transaction, or NFT recipient.

## Failure and Security Behavior

- An unpaid request receives HTTP 402 and never reaches business logic.
- An invalid, expired, insufficient, wrong-network, or replayed credential is
  rejected by the SDK and never reaches business logic.
- Broker verification or settlement failure is fail-closed; the request must not
  receive the paid resource for free.
- Missing/partial production credentials prevent gateway startup.
- Free endpoints do not depend on the Broker after the gateway has started.
- Cachet's existing error envelope remains in use for business errors after a
  successful settlement.
- Automatic refunds for a business failure after settlement are outside the
  hackathon scope. Callers should provide `request_id` so Cachet's existing
  idempotency mechanism prevents duplicate business operations.
- Tests and operational commands must never print OKX credentials or payment
  credentials. Repository searches must explicitly exclude `.env`.
- The replacement key is entered directly on the VPS only after the new gateway
  image is ready. It is never copied through chat or committed to git.

## Verification Strategy

### Local, secret-free verification

- Unit-test the four route/price mappings and free-route exclusions.
- Test configuration validation for missing, complete, and partial credentials.
- Use an injected fake facilitator/Broker transport to test:
  - unpaid request -> compliant x402 v2 challenge;
  - accepted credential -> handler executes and receipt is returned;
  - rejected credential -> handler does not execute;
  - Broker failure -> request fails closed.
- Update MCP tests to assert v2 challenge passthrough and current header wording.
- Run gateway tests and TypeScript typechecking.
- Build the gateway Docker image locally for `linux/amd64`.

### Public testnet verification (A5.4)

1. Add the new OKX credentials directly to `/opt/cachet/.env` with `sudoedit`.
2. Deploy/recreate only the Cachet gateway container.
3. Confirm gateway health, public HTTPS, free certificate lookup, and unpaid 402.
4. Fund a separate buyer wallet with official X Layer testnet faucet assets.
5. Call `/v1/verify` through an external OKX-compatible buyer and prove
   `402 -> sign/pay -> replay -> 200` with a valid Originality Profile.
6. Call `/v1/mint` with a fresh fixture and `request_id`, then verify the new NFT
   and transaction in the X Layer Testnet explorer.
7. Confirm SimpleArt remained healthy throughout the gateway-only replacement.

If the gateway or paid smoke test fails, restore the previous immutable gateway
image. The engine and SimpleArt are not replaced.

### Marketplace verification

ASP registration occurs only after the direct public smoke test passes. Once the
listing is accepted, repeat the paid Golden Path through OKX.AI. This is the final
post-listing marketplace acceptance and is distinct from A5.4.
